# システム構成

- データベースは MySQL8

# ディレクトリ構成

- バックエンドのディレクトリは backend/go
  - エントリポイントは go/cmd/server/main.go です
  - マイグレーションファイルは go/internal/common/db/migration
  - システム共通のモデルは go/internal/domain に定義
  - API は go/internal の下になるべくモデルに基づく単位でディレクトリを作成する
  - エラーコードは go/internal/common/errors/errors.go に定義して使います
- フロントエンドのディレクトリは frontend
  - ログインは app/login
  - 管理者が使える管理画面は app/admin
  - 一般ユーザー、管理者ともに使用できる機能は、app/(main) の中に機能ごとのディレクトリを作成
  - page.tsx から使用するコンポーネントごとの機能は、app/features の中に機能ごとのディレクトリを作成
  - API 実行時の共通処理は lib/api
  - 共通 UI コンポーネントは components/ui
  - サイドメニューは app/(main)/layout.tsx, app/admin/layout.tsx にそれぞれあるので、機能追加時はここにメニューを追加する

# コーディングルール

- バックエンド
  - controller, service, repository を作る
  - dto を作成する
  - エラーは errors.go に定義して使う
- フロンエンド
  - as を使ったアサーションは可能な限り避ける
  - 即時実行関数は使わない
  - 型が自動推論できる場合は明示しない
  - データの取得はカスタムフックを定義してデータを取得する
  - page.tsx に UI やイベントハンドラの実装は書かず、エントリポイントになるコンポーネントに、URL から取得したパラメータだけを渡すようにする
  - 1 つの tsx ファイルはなるべく小さくなるように、コンポーネント化を行う
  - async/await を優先し、then/catch はなるべく使わない
  - ジェネリクスを使用して型を明確にし、処理をなるべくシンプルにする
  - UI 作成時、なるべく共通 UI コンポーネントを使うようにする。共通 UI コンポーネントがなく、汎用的なコンポーネントと判断した場合は、新しく共通 UI コンポーネントを作成する
  - 共通 UI コンポーネントの追加、変更時は storybook も作成、更新する
  - 機能ごとのサーバーアクションを作ったとき、lib/actions/index.ts でエラープロキシの登録をすること

# その他のルール

- コードを追加したときは、合わせてテストコードを作成する
- コード変更時はテストコード修正し、テストを実行して問題ないことを確認する
